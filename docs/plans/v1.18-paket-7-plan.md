**Grundlage:** dieses Paket kombiniert die generische `/release`-Skill-Kette
(Test-/Build-Gate, Code-Review-Gate, Version, Release Notes,
Store-Metadaten, ASC-Push, Tag) mit den V1.18-spezifischen
Release-Kriterien aus `docs/2026-09-08-v1.18-release-plan.md` §9, die über
den generischen Skill-Umfang hinausgehen: Migrationstest V1.17→V1.18 mit
Bestandsbibliothek, Cloud an/aus + Backup-Roundtrip, Datenrollback,
TestFlight auf realem Gerät. Laut Playbook-Lesson „Upgrade-Tests niemals per
Xcode-Dev-Build über App-Store-Version ausführen" (Release.md
„Lessons Learned") müssen diese Prüfungen auf einem echten Gerät über
TestFlight/Ad-Hoc laufen, nicht im Simulator und nicht per Dev-Build über
eine App-Store-Installation — das bleibt daher zwingend ein manueller
Schritt, wie schon Archive/Upload in der `/release`-Skill.

## P7-A — Voller Testlauf + Release-Build

  Simulator,name=<verfuegbares iPhone>'` — Befund `** TEST SUCCEEDED **`,

  `SchemaMigrationV8toV9Tests`, `MigrationSafetyTests` ab (automatisierter
  Teil der Migrationsabnahme; der Realgeraet-Teil bleibt P7-G).

  CODE_SIGNING_ALLOWED=NO` — Release-Build-Pfad ohne Signing gruen.
- Jeder Fehlschlag stoppt das Paket ohne Override (Skill-Regel).

## P7-B — Code-Review-Gate

- Letzter Tag `v1.17` ist bereits ausgeliefert (Release.md Submission Log
  2026-08-25) → Diff `v1.17..HEAD` ist der volle V1.18-Umfang (Paket 0–6,
  ~60 Commits).
- Review per `/code-review`-Skill auf den Diff, Fokus Korrektheit +
  offensichtliche Bloedsinnsfehler — kein Stil-Nitpicking, das faellt unter
  die bereits einzeln abgenommenen Paket-Reviews.
- Kritische Befunde blockieren bis Fix oder ausdrueckliche
  Nutzer-Freigabe ("bewusst so", im Review-Ergebnis dokumentiert).

## P7-C — Versions-Bump

- Naechste Version aus Aenderungsart vorschlagen: V1.18 bringt neue
  Features (FR-Sprache, Anthologie-Pfad, Neuigkeiten, SchemaV9) → `1.18`,
  passend zum bereits in Roadmap/Release-Plan gefuehrten Namen.
- Nach Bestaetigung: `agvtool new-marketing-version 1.18`,
  `agvtool next-version -all`. Bekannte Falle (Release.md
  „Lessons Learned" v1.16.1): `agvtool` kann `$(MARKETING_VERSION)` in
  Info.plists durch Literale ersetzen statt Build-Settings zu aktualisieren
  — Diff vor dem Commit pruefen, im Zweifel manuell in `project.pbxproj`.
- Commit `chore: bump version to 1.18 (<build>)`.

## P7-F — Push nach ASC

- `fastlane deliver --api_key_path ~/.appstoreconnect/key.json
  --app-version 1.18 --skip-screenshots --skip-binary-upload`.
- Bekannte Faktoren aus fruesheren Releases (Release.md): ggf.
  `LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8` falls Umlaute/Akzente den Renderer
  crashen (jetzt auch FR mit Akzenten relevant), `deliver` fragt selbst
  interaktiv nach Bestaetigung — kein `--force` ohne ausdrueckliche
  Nutzerfreigabe des Push-Zeitpunkts.
- Metadaten fuer eine neue Version koennen vor jedem Build in ASC gepusht
  werden.
