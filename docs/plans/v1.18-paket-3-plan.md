## P3-A — SchemaV9

**Dateien:** `EpisodeTracker/Shared/App/SchemaVersions.swift`,
`EpisodeTracker/Shared/App/EpisodeTrackerMigrationPlan.swift`,
`EpisodeTracker/Shared/Models/Universe.swift`,
`EpisodeTrackerTests/SchemaMigrationV8toV9Tests.swift` (neu).

1. `git show <1.17-Tag oder 9568ac3>:EpisodeTracker/Shared/App/SchemaVersions.swift`
   und die drei Live-Modelldateien ziehen. Den heutigen `enum SchemaV8` durch
   explizite Snapshot-`@Model`-Klassen ersetzen — `Episode`, `Mood`, `Universe`
   in exakt der 1.17-Form. `@Relationship` mit Inverse / `originalName` /
   Delete-Rule vollständig übernehmen. `SchemaV8.Universe`: `id`, `name`,
   `syncKey`, `coverImageName`, `styleRaw`, `episodeRelationships`.
2. Neuer `enum SchemaV9: VersionedSchema` — `versionIdentifier = Schema.Version(9,
   0, 0)`, `models { [Episode.self, Mood.self, Universe.self] }` (Live).
3. `Universe.swift`: `var managedCatalogID: String?` als gespeicherte Property
   (kein Default). Kein `init`-Parameter zwingend nötig; optionaler Parameter mit
   Default `nil` erlaubt, wenn Aufrufkomfort hilft.
4. `EpisodeTrackerMigrationPlan`: `schemas` um `SchemaV9.self` erweitern, `stages`
   um `migrateV8toV9 = MigrationStage.lightweight(fromVersion: SchemaV8.self,
   toVersion: SchemaV9.self)`.
5. `AppModelContainerFactory.schema()` **nicht** anfassen (bleibt Live-Schema).
6. Test `SchemaMigrationV8toV9Tests`: einen Store mit der **eingefrorenen**
   `SchemaV8`-Definition schreiben (Universe + Episoden + Moods + Relationship),
   schließen, mit `EpisodeTrackerMigrationPlan` + Live-Schema öffnen, prüfen:
   Store wird als V8 erkannt, migriert nach V9, alle Objekte + Beziehungen
   erhalten, `managedCatalogID == nil`. Zusätzlich bestehende
   `SchemaMigration…Tests` weiter grün (pre-V8-Kette).

**Playbook-Fallen:** Snapshot exakt treffen (sonst „unknown model version“); den
Alt-Store im Test **nicht** aus derselben Definition schreiben, gegen die geprüft
wird — hier akzeptabel, weil die eingefrorene V8 den 1.17-Stand transkribiert und
der Prüfgegenstand die V8→V9-Stage plus Live-Schema ist. Zusätzlich einen
manuellen Upgrade-Pfad-Test vormerken (1.17-Build → Daten → V9-Build drüber) für
P3-H.

**Dateien:** `EpisodeTracker/Features/Catalog/CatalogLanguageFilterStore.swift`

`CatalogManagementView.swift` (Filter-UI), `Localizable.xcstrings`,

   `catalogLanguageFilter` (`[String]?`). `selectedLanguages: Set<String>` —

   „Weitere Sprachen“ die den Filter auf `allKnownSources`-Sprachen weitet.

## Reihenfolge-Hinweise

- P3-A ist Voraussetzung für alles Weitere (das Feld muss existieren).
- P3-C liefert `allKnownSources`, das P3-B (Adoption) und P3-D (Filter) nutzen —
  P3-B kann zunächst gegen `managedSources` schreiben und in P3-C nachziehen, oder
  P3-C vor P3-B ziehen. Empfehlung: **P3-A → P3-C → P3-B → P3-D → P3-E → P3-F →
  P3-G → P3-H**.
- P3-F und P3-G sind unabhängig von P3-D/P3-E und könnten früher laufen, ändern
  aber nichts an der Empfehlung.
