Stand: 2026-09-10. Feature-Spec, keine Implementierung. Abgeleitet aus

## 1. Ziel

Eine Sammlung eindeutig an eine verwaltete Katalogquelle binden (nicht mehr nur
über den normalisierten Namen), das Backup-Format diese Bindung mittragen lassen,
die Katalog-Registry von den im UI sichtbaren Quellen trennen, einen
gerätebezogenen Mehrfach-Sprachfilter unter „Reihen auswählen“ einführen und beim
Aktivieren einer Quelle sofort deren Katalog laden.

Alles additiv und sprachunabhängig. Bestehende Datensätze dürfen unter keinen
Umständen kaputtgehen (stehende Nutzer-Randbedingung, Playbook „Data & Sync“
Goldene Regel 1).

## 4. Datenvertrag der Entscheidungen

### D1 — SchemaV9: SchemaV8 einfrieren, `Universe.managedCatalogID` hinzufügen

Ein Commit (Playbook Goldene Regel 5: Einfrieren und erste echte Änderung
gehören zusammen, sonst kollidieren die Prüfwerte).

- **`SchemaV8` einfrieren:** explizite `@Model`-Snapshot-Klassen für `Episode`,
  `Mood`, `Universe` — Property für Property aus dem 1.17-Auslieferstand
  transkribiert (`git show`, **nicht** aus der aktuellen Datei ableiten; Playbook
  „Migrationstest, der sich nicht selbst bestätigt“). `@Relationship`
  vollständig mit Delete-Rule, Inverse und `originalName` (Playbook BoardGameLog).
  `SchemaV8.Universe` trägt genau: `id`, `name`, `syncKey`, `coverImageName`,
  `styleRaw`, `episodeRelationships`.
- **`SchemaV9`:** `versionIdentifier (9,0,0)`, `models` referenzieren die
  Live-Modelle.
- **Live-`Universe`** bekommt `var managedCatalogID: String?` (optional, kein
  Default nötig — Lightweight- und CloudKit-sicher).
- **Plan:** `schemas` → `[…, SchemaV8.self, SchemaV9.self]`, `stages` → `[…,
  migrateV8toV9]` mit `MigrationStage.lightweight(fromVersion: SchemaV8.self,
  toVersion: SchemaV9.self)`.
- `AppModelContainerFactory.schema()` bleibt `Schema([Episode.self, Mood.self,
  Universe.self])` — unverändert; der Plan trägt V9.
- Kein Custom-Stage, kein Backfill in der Migration (CloudKit-Regel). Backfill der
  Bindung ist eine App-Level-Migration → D3.

### D2 — Bindung wird beim Aktivieren gesetzt

`CatalogManagementView.toggleCatalog(source:active:true)`:
- neu angelegte `Universe` → `managedCatalogID = source.id`.
- bestehende, per normalisiertem Namen gematchte, **ungebundene** `Universe` →
  `managedCatalogID = source.id`.
- bestehende `Universe` mit **abweichender** nicht-`nil`-Bindung → **nicht
  überschreiben** (Identität eingefroren, analog Sonderfolgen-Slug). Kein Fehler,
  nur kein Schreibvorgang.
Deaktivieren lässt `managedCatalogID` unverändert (§3: Reaktivieren lädt nach).

### D3 — Adoption bestehender Zuordnungen (App-Level-Migration)

`AppDataBootstrapper.adoptCatalogBindingsIfNeeded(container:)`:
- idempotent, über `UserDefaults`-Flag `hasRunCatalogBindingAdoptionV9` gegated
  (Playbook: wertbasierte Transformationen als App-Level-Migration, nicht als
  CloudKit-Custom-Stage).
- für jede `Universe` mit `managedCatalogID == nil`: Match gegen die **volle
  Registry** (`allKnownSources`, D4) über den normalisierten Namen
  (`CatalogLibraryMatcher.normalizedCollectionKey`).
- Bindung nur bei **genau einem** Treffer. Mehrdeutig (zwei Registry-Quellen mit
  gleichem normalisierten Namen) oder kein Treffer → `nil` lassen, Zähler loggen.
- läuft im Bootstrap neben `reconcileCatalogStyles`, unabhängig vom Netz.

### D4 — Vollständige Registry vs. sichtbare Quellen

`CatalogSourceRegistry`:
- **`allKnownSources`** — jede Quelle aus Manifest bzw. `fallbackManagedSources`,
  **ohne** Sprachfilter. Die „vollständige Registry“ (§3: „Entfernte Kataloge
  werden nur gegen ein erfolgreich validiertes vollständiges Manifest
  festgestellt“).
- **`visibleSources`** — `allKnownSources` gefiltert über das gewählte
  Katalogsprachen-Set (D5). Ersetzt den heutigen impliziten Hartfilter
  `.matchesDeviceLanguage`.
- `managedSources` bleibt als **Alias auf `visibleSources`** bestehen, damit
  bestehende Aufrufstellen unverändert korrekt sind; wo „alle bekannten“ gemeint
  sind, wird auf `allKnownSources` umgestellt.
- `ActiveCatalogStore.pruneOrphanedIDs()` / `defaultActiveIDs()` schlüsseln auf
  **`allKnownSources`**. Eine aktive Bindung an eine nur vom Sprachfilter
  verborgene Quelle wird **nie** geprunt; geprunt wird nur, was in einem
  erfolgreich validierten vollständigen Manifest fehlt.
- Der NSLock-Cache in `CatalogSourceRegistry` deckt beide abgeleiteten Listen ab;
  Invalidierungspfade: `CatalogCacheStore.saveManifest` **und** Änderung des
  Sprachfilters (invalidiert nur `visibleSources`).

### D5 — Katalogsprachen-Filter (§3 Regel 2)

- `CatalogLanguageFilterStore` über `UserDefaults` (Schlüssel
  `catalogLanguageFilter`), Wert = `Set<String>` von Sprachcodes. Gerätebezogen,
  **keine** neue Cloud-Synchronisierung (§5).
- Kein Eintrag ⇒ impliziter Default `{ App-Sprache }`. Leerer Trefferzustand
  bietet „Weitere Sprachen“.
- Eine **ausdrücklich** gewählte Auswahl bleibt bei UI-Sprachwechsel erhalten
  (§3).
- Mehrfachauswahl, unauffällig, **nur** unter „Reihen auswählen“
  (`CatalogManagementView`). Kein Hauptbildschirm-Filter, kein Einrichtungsschritt.
- Bereits **aktive / gebundene** Reihen bleiben sichtbar und aktiv, unabhängig vom
  Filter (§3). Der Filter steuert ausschließlich `visibleSources`; er fasst
  `activeIDs` und `managedCatalogID` **nie** an.
- Neue UI-Strings sofort mit `en`-Wert im String-Katalog (Memory
  `feedback_xcstrings_english_check`).

### D6 — Sofortiger Download beim Aktivieren

`toggleCatalog(source:active:true)` nach dem Setzen der Bindung:
- `Task { await EpisodeCatalog.shared.refreshManagedCatalog(universeName:
  source.name, force: true) }` — der bestehende Einzelquell-Refresh, umgeht den
  6-h-Cooldown. **Keine** neue Fetch-Infrastruktur.
- Inline-Zeilenstatus in der bestehenden Katalogliste: Laden (Spinner),
  Erfolg (aktualisiert die „N Titel“-Subzeile), Fehler → typisierter Fehlertext
  + „Erneut versuchen“ (nutzt `CatalogRefreshOutcome` / `lastRefreshError` aus
  Paket 2).
- Fetch-Fehler rollt die Aktivierung **nicht** zurück (§4.A: „Bei Fehler bleibt
  die Abonnemententscheidung erhalten“).
- Wiederholtes Tippen legt **keine** zweite `Universe` an und stößt **keinen**
  zweiten Fetch an, solange der erste läuft.
- Kein „0 Folgen“ für ungeladene Daten (§4.A). Deaktivieren löscht weder
  Episoden noch Cache (§3).
- **Nicht** enthalten: eigener Reihenvorschau-Screen (Name/Sprache/Umfang/Quelle/
  Datenstand als Ansicht) → Paket 6.

### D7 — Backup-Format v2

- `BackupCollection` bekommt `managedCatalogID: String?` und `style: String?`
  (beide optional).
- `BackupPayload.schemaVersion` 1 → 2.
- **Reader:** Backups ohne die Felder / `schemaVersion == 1` importieren
  unverändert — Universe bleibt ungebunden, Stil `.numbered` wie heute.
- **Writer:** emittiert die neuen Felder.
- `BackupRestorer`-Merge: auf einer namensgematchten bestehenden `Universe`
  `managedCatalogID` nur setzen, wenn aktuell `nil` (eine abweichende lokale
  Bindung nicht klobbern); `style` wie heute.
- Export-/Import-Roundtrip erhält Bindung und Stil.

### D8 — CloudKit-Dedupe erhält Bindungen

`EntityDeduplicator.deduplicateUniverses` (in `SyncPreparation`), beim Mergen
zweier Universes gleicher Sync-Identität:
- beide tragen eine **nicht-`nil`, verschiedene** `managedCatalogID` → **nicht
  mergen**, beide behalten (§5: „widersprüchliche Bindungen nicht
  zusammenführen“). `SyncPreparationSummary` zählt
  `skippedConflictingBindingMerges`.
- genau eine trägt eine Bindung → Survivor erhält sie.
- beide gleich (oder beide `nil`) → mergen wie heute.
Additiv zur bestehenden syncKey-/ID-Reparatur.

### D9 — Ausdrücklich außerhalb von Paket 3

- Polierte Reihenvorschau als eigener Screen → Paket 6.
- Rename „Reihen entdecken“ → „Reihen auswählen“ und die Vereinheitlichung
  beider Einstiege (§4.A) → Paket 6, außer es fällt hier kostenlos ab.
- FR-Pilotkataloge / Befüllen der Registry mit (verborgenen) FR-Quellen →
  Paket 5 (Paket-0-blockiert).
- Widget-Snapshot-Erweiterung für ID-basierte Auswahl (§5) → nur falls Paket 4 es
  braucht.
- Cloud-Sync des Sprachfilters oder der `activeIDs` — bleibt gerätebezogen (§5).
- Neuigkeiten-Store (§5) → Paket 4.

## 5. Abnahmekriterien (§8 Prüfung: „Upgrade, gemischte Sprachen, Backup/Cloud“)

1. **Upgrade 1.17 → V9** mit bestehender Bibliothek: staged migration erkennt den
   Store als V8, Lightweight → V9, alle Universes/Episodes/Moods intakt,
   `managedCatalogID` zunächst `nil`, dann von der Adoption bei eindeutigem Match
   gefüllt. Alt-Store-Smoke (vor V8) migriert weiter durch die volle Kette.
2. **Frischinstallation:** SchemaV9-Store, keine Migration; Aktivieren bindet und
   lädt.
3. **Adoption idempotent:** läuft genau einmal (Flag), zweiter Start ist No-op;
   mehrdeutige Namen bleiben ungebunden.
4. **Sprachfilter:** Default = App-Sprache zeigt denselben Satz wie heute;
   Erweitern zeigt mehr; ausdrückliche Auswahl übersteht einen UI-Sprachwechsel;
   aktive / gebundene Reihen immer sichtbar; leerer Treffer bietet „Weitere
   Sprachen“.
5. **Registry/Sichtbarkeit:** eine Bindung an eine vom Filter verborgene Quelle
   wird nicht geprunt; eine in einem validierten vollständigen Manifest fehlende
   Quelle wird geprunt (und ihre aktive ID bereinigt).
6. **Sofort-Download:** Aktivieren online → Titel erscheinen ohne Neustart;
   Aktivieren offline → Aktivierung bleibt, Fehler + „Erneut versuchen“;
   wiederholtes Tippen ohne Doppel-`Universe` / Doppel-Fetch.
7. **Backup-Roundtrip:** Export mit gebundenen + gestylten Sammlungen → löschen →
   Import → Bindungen und Stile wiederhergestellt; ein `schemaVersion`-1-Backup
   importiert weiterhin.
8. **Cloud:** zwei Geräte binden dieselbe gleichnamige Sammlung an verschiedene
   Katalog-IDs → Dedupe lässt beide stehen, kein stiller Merge; gleiche Bindung
   auf beiden → mergt einmal.
9. Vollständiger Testlauf grün + Release-Build; `Localizable.xcstrings` hat `en`
   für jeden neuen UI-String.

## 6. Risiken

- **SchemaV8-Fingerprint.** SchemaV8 referenziert heute Live-Modelle; der
  1.17-Store hat den Fingerprint „Live-Modelle Stand 1.17“. Der eingefrorene
  Snapshot muss diese Form **exakt** treffen, sonst „unknown model version“.
  Gegenmittel: `git show <1.17>` transkribieren; Migrationstest muss gegen einen
  **nicht** aus derselben Snapshot-Definition geschriebenen Alt-Store laufen.
- **`managedSources`-Alias.** Solange `managedSources == visibleSources`, ändert
  der Split das Verhalten für die fünf DE-Kataloge nicht (App-Sprache DE ⇒ Filter
  Default `{de}` ⇒ dieselbe Liste wie der heutige `.matchesDeviceLanguage`).
  Regressionsrisiko liegt in Prune-/Default-Pfaden, die auf `allKnownSources`
  wechseln.
- **CloudKit-Merge-Verzicht.** Zwei widersprüchlich gebundene Universes stehen zu
  lassen kann als „Duplikat“ erscheinen. Bewusst — §5. Das bestehende
  Duplikat-Dismissal-Muster (Playbook) deckt die UI-Seite ab, falls nötig.
