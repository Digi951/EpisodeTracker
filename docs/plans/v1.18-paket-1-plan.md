## Commit P1-B — `CatalogEntry` + `CatalogParser` um V2-Provenienzfelder erweitern

**Ändern:** `EpisodeTracker/Features/Catalog/CatalogModels.swift` — `CatalogEntry`
- Neue stored properties:
  ```swift
  let releaseDate: Date?
  let releaseStatus: CatalogReleaseStatus   // Default .unknown
  let sourceCheckedAt: Date?
  let changedAt: Date?
  ```
- `CodingKeys`: `releaseDate`, `releaseStatus`, `sourceCheckedAt`, `changedAt` ergänzen.
- `init(from:)`:
  - `releaseStatus = CatalogReleaseStatus.resolve(try container.decodeIfPresent(String.self, forKey: .releaseStatus))`
  - `releaseDate` / `sourceCheckedAt` / `changedAt`: `decodeIfPresent(String.self, …)` →
    `CalendarDayFormatter.date(from:)`. **Wichtig:** ein vorhandener, aber
    falsch getypter Wert (Zahl) muss werfen. Muster:
    ```swift
    if let raw = try container.decodeIfPresent(String.self, forKey: .releaseDate) {
        guard let d = CalendarDayFormatter.date(from: raw) else {
            throw DecodingError.dataCorruptedError(forKey: .releaseDate, in: container,
                debugDescription: "Erwartet yyyy-MM-dd, gelesen \"\(raw)\"")
        }
        releaseDate = d
    } else { releaseDate = nil }
    ```
    (`decodeIfPresent(String…)` wirft bei `123` bereits einen Typmismatch — die
     `guard` fängt nur den Fall „String, aber kein Datum". Beides = Fail-Fast.)
- `encode(to:)`: die vier Felder mit `encodeIfPresent` (Datumsfelder über
  `CalendarDayFormatter.string(from:)`), `releaseStatus` immer schreiben
  (`encode`), damit der Cache-Roundtrip sie erhält.
- **Beide** `init(...)`-Convenience-Overloads: vier Parameter ergänzen,
  `releaseDate: Date? = nil`, `releaseStatus: CatalogReleaseStatus = .unknown`,
  `sourceCheckedAt: Date? = nil`, `changedAt: Date? = nil`. An den designierten
  `init` weiterreichen.
- `hasStreamingLink` / `preferredLink` / `sourceURL` / `sanitized` unverändert.

**Ändern:** `EpisodeTracker/Features/Catalog/CatalogParser.swift`
- `CatalogDocument`: `let catalogFormat: Int?` ergänzen.
- `NormalizedCatalogDocument`: `let catalogFormat: Int?` ergänzen, in
  `parseNormalizedCatalogDocument` aus `document.catalogFormat` bzw. `nil`
  (Flat-Array-Zweig) setzen.
- In **allen drei** `CatalogEntry(number: … )`-Neuaufbauten (`parseCatalogEntries`,
  `parseNormalizedCatalogDocument` ×2) die vier neuen Felder mit-durchreichen:
  `releaseDate: $0.releaseDate, releaseStatus: $0.releaseStatus,
  sourceCheckedAt: $0.sourceCheckedAt, changedAt: $0.changedAt`.

**Tests:** `EpisodeTrackerTests/CatalogDataContractTests.swift` (Swift Testing) —
Tests 1–7 aus Spec §8.2 + Fixtures `catalog_v2_numbered.json`,
`catalog_v2_anthology.json`, `catalog_legacy_flat.json`,
`catalog_v2_unknown_fields.json`, `catalog_v2_bad_status.json`,
`catalog_v2_wrong_type.json` (Spec §8.1).

**Gate:** neue Tests grün + voller Testlauf grün (bestehende Catalog-Suites nur
durch Default-Parameter kompiliert, kein Logikbruch).

**Commit:** `feat: carry V2 provenance fields on CatalogEntry (decode/encode, no UI)`

## Commit P1-C — Terminfeed additiv: optionale `number`, `slug`, `releaseStatus`, `feedVersion`

**Ändern:** `EpisodeTracker/Features/Catalog/UpcomingRelease.swift`
- `number: Int` → `number: Int?`; `slug: String?` + `releaseStatus: CatalogReleaseStatus` ergänzen.
- `CodingKeys`: `slug`, `releaseStatus` ergänzen.
- `id`: `"\(catalogID)-\(number.map(String.init) ?? slug ?? "?")"`.
- `init(from:)`:
  - `number = try container.decodeIfPresent(Int.self, forKey: .number)`
  - `slug = try container.decodeIfPresent(String.self, forKey: .slug)`
  - `guard number != nil || slug != nil else { throw DecodingError.dataCorrupted(...) }`
  - `releaseStatus = .resolve(try container.decodeIfPresent(String.self, forKey: .releaseStatus))`
    — Default hier `.announced`? Nein: `.resolve(nil) == .unknown`. Feed-Semantik
    „fehlt ⇒ announced" über eine kleine lokale Abbildung:
    `let s = CatalogReleaseStatus.resolve(raw); releaseStatus = (raw == nil) ? .announced : s`.
  - `releaseDate` unverändert (Pflicht, wirft bei Fehlen/Fehlformat).
- `encode(to:)`: `number`/`slug` mit `encodeIfPresent`, `releaseStatus` mit `encode`.
- `UpcomingReleasesDocument`: `let feedVersion: Int?` (`decodeIfPresent`).

**Ändern:** `EpisodeTracker/Features/Catalog/UpcomingReleasesFeed.swift`
- `.sorted { ($0.releaseDate, $0.number) < ($1.releaseDate, $1.number) }`
  → `.sorted { ($0.releaseDate, $0.number ?? .max, $0.slug ?? "") < ($1.releaseDate, $1.number ?? .max, $1.slug ?? "") }`.
- `.filter`-Zeile unverändert (kein `number`-Zugriff).
- Prüfen, ob `Row`/`visibleReleaseIDs` `number` nicht-optional erwarten — ggf.
  `id` (String) statt `number` verwenden. Keine UI-Änderung an `UpcomingReleasesSheet`
  über das mechanisch Nötige hinaus.

**Tests:** Contract-Tests 8–9 + Fixtures `upcoming_feed_v2.json`,
`upcoming_feed_v2_idless.json`. Zusätzlich Snapshot-Test der Sortierreihenfolge
mit gemischten `number`/`slug`-Zeilen (Risiko §11).

**Gate:** neue Tests grün + `EpisodeCatalogUpcomingReleasesTests`,
`CatalogCacheStoreUpcomingReleasesTests` unverändert grün + voller Testlauf grün.

**Commit:** `feat: allow anthology rows in the upcoming-releases feed (optional number + slug)`
